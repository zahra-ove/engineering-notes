## تفاوت go.sum و GOSUMDB در Go

در Go هنگام کار با dependencyها دو مفهوم مهم وجود دارد:

### 1) go.sum

فایلی داخل خود پروژه است.

* توسط خود Go ساخته و آپدیت می‌شود.
* شامل checksum (هش) ماژول‌ها و نسخه‌های آن‌هاست.
* باید همراه پروژه در Git commit شود.
* وظیفه‌اش این است که مطمئن شود dependency دانلودشده دقیقاً همان چیزی است که قبلاً تأیید شده.

مثال:

```
go.mod
go.sum
main.go
```

---

### 2) GOSUMDB

یک دیتابیس خارجی است، نه بخشی از پروژه.

* به صورت پیش‌فرض به این آدرس وصل می‌شود:

```
sum.golang.org
```

* هنگام دانلود dependency، Go checksum را با این سرویس بررسی می‌کند.
* هدفش جلوگیری از تغییر یا دستکاری dependencyهاست.

---

### جریان کلی:

```
go mod download
        |
        ▼
دریافت ماژول از GOPROXY
        |
        ▼
بررسی checksum با GOSUMDB
        |
        ▼
ثبت checksum در go.sum
```

---

### نکته مهم:

* `go.sum` داخل پروژه است و باید در Git باشد.
* `GOSUMDB` بیرون از پروژه است و فقط یک سرویس بررسی اعتبار است.
* خاموش کردن `GOSUMDB` (`GOSUMDB=off`) فقط بررسی آنلاین checksum را غیرفعال می‌کند و معمولاً راه‌حل اصلی مشکلات دانلود dependency نیست.

---

خلاصه یک خطی:

**go.mod می‌گوید چه dependencyهایی لازم داریم، go.sum اثر انگشت (checksum) آن‌ها را نگه می‌دارد، و GOSUMDB مرجع بیرونی برای تأیید این اثر انگشت‌هاست.**

حتماً. این جدول رو می‌تونی برای یادداشت‌هات نگه داری:

| دستور                                                           | وظیفه                                                      | چه چیزی را تغییر می‌دهد؟      | چه زمانی استفاده می‌شود؟                                                                        | مثال سناریو                                                                                                    |
| --------------------------------------------------------------- | ---------------------------------------------------------- | ----------------------------- | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `go env -w GOPROXY=https://hub.megan.ir/go,direct`              | تعیین می‌کند Go dependencyها را از کجا دانلود کند          | مسیر دانلود ماژول‌ها          | وقتی دسترسی به `proxy.golang.org` مشکل دارد، سرعت پایین است یا شرکت یک Proxy داخلی دارد         | در شبکه سازمانی که دسترسی به اینترنت محدود است، به جای دانلود مستقیم از اینترنت از Proxy داخلی استفاده می‌کنیم |
| `go env -w GOSUMDB="sum.golang.org https://hub.megan.ir/sumdb"` | تعیین می‌کند Go checksum ماژول‌ها را از کجا اعتبارسنجی کند | منبع بررسی صحت `go.sum`       | وقتی دسترسی به `sum.golang.org` مشکل دارد یا سازمان یک mirror داخلی برای checksum database دارد | شرکت یک SumDB داخلی ساخته تا توسعه‌دهنده‌ها بدون دسترسی مستقیم به سرویس گو بتوانند checksumها را بررسی کنند    |
| `go env -w GOFLAGS="-mod=vendor"`                               | به Go می‌گوید dependencyها را از پوشه `vendor` بخواند      | روش resolve کردن dependencyها | وقتی پروژه پوشه `vendor` دارد و نمی‌خواهیم هنگام build چیزی از اینترنت دانلود شود               | پروژه‌های سازمانی، محیط‌های بدون اینترنت یا CI/CDهای ایزوله                                                    |

---

### ارتباط این سه با هم:

حالت عادی:

```
go build
    |
    ↓
GOPROXY
    |
    ↓
دانلود dependency
    |
    ↓
GOSUMDB
    |
    ↓
بررسی checksum
    |
    ↓
استفاده از dependency
```

اما وقتی vendor فعال باشد:

```
go build
    |
    ↓
GOFLAGS=-mod=vendor
    |
    ↓
پوشه vendor
    |
    ↓
بدون دانلود از اینترنت
```

---

### یک نکته مهم درباره `vendor`

اگر پروژه `vendor` نداشته باشد:

```bash
go env -w GOFLAGS="-mod=vendor"
```

ممکن است باعث خطا شود، چون Go دنبال dependencyها در پوشه‌ای می‌گردد که وجود ندارد.

برای ساخت vendor معمولاً از این استفاده می‌شود:

```bash
go mod vendor
```

که نتیجه‌اش ایجاد پوشه:

```
vendor/
```

است.

---

خلاصه خیلی کوتاه:

* **GOPROXY → از کجا دانلود کنم؟**
* **GOSUMDB → از کجا مطمئن شوم دستکاری نشده؟**
* **GOFLAGS=-mod=vendor → اصلاً دانلود نکن، از فایل‌های داخل پروژه استفاده کن.**
