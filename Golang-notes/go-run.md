تفاوت go run file.go و go run . در Go

1. اجرای یک فایل مشخص:

```bash
go run main.go
```

* فقط همان فایل `main.go` کامپایل و اجرا می‌شود.
* فایل‌های دیگر `.go` در همان پوشه وارد build نمی‌شوند.
* برای مثال اگر تابعی در `helper.go` باشد، با اجرای فقط `main.go` شناخته نمی‌شود.

---

2. اجرای package فعلی:

```bash
go run .
```

* نقطه (`.`) یعنی package فعلی را اجرا کن.
* تمام فایل‌های `.go` موجود در آن package که package مشابه دارند، با هم build می‌شوند.
* روش استاندارد در پروژه‌های واقعی Go است.

---

3. نقش فایل go.mod:

`go.mod` هویت یک پروژه Go را مشخص می‌کند.

اطلاعاتی مثل:

* نام module
* نسخه Go
* dependencyهای پروژه

در آن قرار دارد.

مثال:

```go
module github.com/example/project
```

با وجود `go.mod`، دستور:

```bash
go run .
```

می‌تواند پروژه را به عنوان یک module بشناسد و importها و dependencyها را درست مدیریت کند.

---

4. اگر go.mod وجود نداشته باشد:

* اجرای مستقیم فایل:

```bash
go run main.go
```

معمولاً کار می‌کند.

* اجرای package:

```bash
go run .
```

در Goهای جدید معمولاً خطا می‌دهد، چون Go نمی‌داند این پروژه متعلق به چه moduleای است.

---

خلاصه:

| دستور            | کاربرد                                    |
| ---------------- | ----------------------------------------- |
| `go run file.go` | اجرای فقط یک فایل مشخص                    |
| `go run .`       | build و اجرای کل package فعلی             |
| `go run ./...`   | اجرای همه packageهای پروژه و زیرمجموعه‌ها |
| `go.mod`         | تعریف هویت پروژه و مدیریت dependencyها    |

در پروژه‌های واقعی Go معمولاً پروژه‌ها دارای `go.mod` هستند و از `go run .` استفاده می‌شود.
